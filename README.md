# ITX 자유석 좌석 매트릭스

> ITX 정기권 자유석 통근자를 위한 개인용 좌석 점유 대시보드 + 상태 기반 알림 PWA.
> **개인 사용 목적의 프로젝트로, 앱스토어·퍼블릭 배포 없이 운영합니다.**

**현재 상태 (2026-08-06)**: Phase 3까지 구현 완료. 실제 코레일 계정으로 매트릭스를 조회하고,
아이폰 홈화면 PWA로 푸시를 받는다. 다음은 Phase 4(EC2 배포). 테스트 351개 통과.

## 무엇이 문제인가

ITX 자유석/입석으로 통근하면, 빈 좌석에 앉아 가기 위해 코레일 앱에서 **검색 구간을 계속 바꿔가며** "지금 앉은 자리가 다음 구간에도 비어있는지"를 수동으로 반복 확인해야 한다. 매일 아침저녁으로 반복되는 이 확인 작업을 대신해주고, 정말 필요한 순간에만 알려주는 도구가 이 프로젝트다.

## 무엇을 하는가

**좌석 × 정차구간 점유 매트릭스**를 한 화면에 보여준다. 열차번호와 구간만 넣으면:

- 내 자리가 어느 역부터 팔렸는지 ("3-7A 수원부터 판매됨")
- 어느 좌석으로 옮기면 하차역까지 안 일어나도 되는지 ("4호차 1B — 서울까지 빈 좌석")
- 아예 앉을 자리가 없어 지하철 환승이 나은지

를 자동 판정해 요약하고, 좌석별 상세는 매트릭스에서 직접 확인한다. **판단은 사용자가 한다** — 이 도구는 판단 재료를 정리해줄 뿐이다.

### 탑승 상태 기계

탑승 중 사용자는 **입석(자리 찾는 중)** 또는 **착석** 상태다. 앱에서 좌석을 선택해 "이 자리에 앉음" 한 번의 탭으로 착석·자리 이동을 반영하고, 이후 판정과 알림이 새 자리 기준으로 따라온다.

### 상태 기반 알림 (5종, 폴링당 1건 합성)

열차 안에서 계속 화면을 볼 수는 없으므로, 정차역 도착 전(-10분/-4분) 자동 조회 후 **상태가 변했을 때만** 푸시를 보낸다.

| 알림 | 언제 |
|---|---|
| 착석 가능 | [입석] 다음 역부터 앉을 수 있는 좌석 다이제스트 |
| 내 자리 판매 | [착석] 내 자리가 남은 구간에서 팔림 → 이동 추천 포함 |
| 구간 연장 | [착석] 취소/환불로 내 자리 이용 가능 구간이 늘어남 |
| 전량 매진 | 남은 구간에 앉을 좌석 없음 → 환승 판단 |
| 갱신 실패 | 조회 실패로 화면 데이터가 낡음 |

채널은 iOS 웹푸시(기본) + 디스코드 웹훅(opt-in 병행).

### 위치 표시

노선 진행바의 현재 위치는 시각표+지연 추정이 기본이고, 앱을 연 순간 폰 GPS로 실측 보정한다(권한 거부 시에도 전 기능 동작). 열차 안 회선 불안정에 대비해 마지막 조회를 로컬 캐시하고 조회 시각을 항상 표시한다.

### 매일 쓰기 위한 것들

- **직전 구간 자동 프리필** — "탑승 종료" 후 탑승 등록 화면에 어제 탄 구간이 이미 들어가 있다. 매일 같은 구간을 타는데 역을 다시 고르게 하지 않는다 (운행일·시각은 항상 현재 기준)
- **역 선택은 필터형 콤보박스** — 여객역 282개를 통짜 드롭다운으로는 못 고른다. 타이핑으로 좁히되 확정값은 언제나 목록에서 고른 역이고, **초성 검색**을 지원한다(`ㅊㅇ` → 천안). 한글 조합 중간 상태(`천아`)에서도 목록이 비지 않는다
- **알림 딥링크** — 푸시를 탭하면 그 구독의 매트릭스가 바로 열린다
- **재시작 내구성** — 폴링 시점을 DB(`next_poll_at`)에 두므로 서버가 재시작해도 조회를 건너뛰거나 중복 실행하지 않는다

## 어떻게 만들어져 있는가

```
iPhone Safari PWA (홈 화면에 추가)
      │ Tailscale ts.net HTTPS + 세션 쿠키
      ▼
FastAPI 단일 앱 (Python 3.12, 컨테이너 1개)
  domain/     매트릭스 병합 + 판정 (순수 함수, 단위 테스트로 잠금)
  adapters/   KorailPort · DelayPort · NotifierPort (외부 연동 격리)
  scheduler/  구독 기반 폴링 (next_poll_at 포인터, 재시작 내구)
  storage/    SQLite
      │
      ▼
코레일 비공식 API (korail2) / 웹푸시 / 디스코드 웹훅
```

핵심 설계 원칙 몇 가지:

- **역/노선을 하드코딩하지 않는다** — 정차역은 열차번호로 조회해 캐시한 것을 쓴다. 도메인 로직에 역 이름이 등장하면 잘못된 것이다. 새 구간 지원에 코드 수정이 필요 없다
- **외부 연동은 전부 Port 뒤로** — 비공식 API는 언제 깨져도 이상하지 않으므로 어댑터만 갈아끼우게
- **조용히 틀리는 곳만 테스트로 잠근다** — 판정·알림 변화 감지는 순수 함수 + pytest 필수, 어댑터는 깨지면 어차피 에러로 드러남
- **알림은 상태 변화에만** — 무시하게 되는 알림은 없느니만 못하다

스택: FastAPI · Pydantic v2 · korail2 · APScheduler · pywebpush · SQLite · uv · React(Vite). 배포는 EC2 t4g.nano(서울) + Docker + Tailscale(인바운드 전면 차단).

### Phase 0 결과가 설계를 바꿨다

검증은 두 번 뒤집혔고 그 과정이 이후 설계를 결정했다.

- **비로그인 조회는 불가능하다.** 로그인·열차조회 모두 `MACRO ERROR`로 막혔다 → 한때 NO-GO. 그래서 **자격증명 저장 설계를 삭제하는 갈래가 사라졌다** (계정을 받아 Fernet으로 암호화해 보관한다)
- **좌석맵 조회는 순수 조회다** — 호출 전후로 예약·장바구니·발권대기에 아무 흔적이 없음을 서로 다른 구간 분할로 2회 재현해 확인했다. 이게 no였으면 프로젝트를 접었다
- **열차번호로 전체 정차역을 얻는 API가 없다** → 공공데이터포털 CSV + 최근 운행일 실적을 열차번호 템플릿으로 캐시하는 방식으로 우회
- **좌석맵은 구매 가능 좌석이 아니라 전체 좌석+상태를 준다** → 구간 병합이 단순 조인으로 끝난다

### Phase 3에서 남은 것

코드는 `dev`에 머지됐고 **푸시 배달 경로는 실기기로 확인됐다** — 아이폰 홈화면 PWA에서 테스트 알림 수신 성공(로컬 iMac을 `tailscale serve`로 신뢰 HTTPS 프록시). 남은 것은 **"역 접근 시 자동 갱신 → 알림 수신"을 실제 출근길에서 한 번 통과시키는 것**이다. 맥이 잠들면 30초 틱이 멈추므로, Phase 4 배포가 이 검증을 푸는 실질적인 열쇠다.

검증 절차와 실패 시 볼 로그는 [DEPLOY.md 10절](./DEPLOY.md)에 있다. 준비 중에 **앱 로그가 한 줄도 나오지 않고 있었다는 것**을 발견해 함께 고쳤다 — uvicorn이 root 로거를 비워두는 탓에 `log.info`가 전부 유실되고 있었고, 배포 후에는 그 로그가 관측 수단의 전부다 (D-39).

## 실행

```bash
uv sync
cp .env.example .env      # SECRET_KEY(Fernet) + VAPID 3종은 직접 채운다
uv run python scripts/gen_vapid.py    # VAPID 키쌍 생성 → 출력 3줄을 .env 에

cd web && npm install && npm run build && cd ..   # FastAPI가 web/dist 를 서빙한다

uv run uvicorn app.main:app --workers 1           # worker는 반드시 1
uv run pytest                                      # 351 통과
```

첫 실행 시 마이그레이션이 자동 적용되고, **첫 가입 계정이 관리자**가 된다. 이후 가입은 잠기며 관리자가 설정 화면에서만 열 수 있다.

**개발 중에는 `ADAPTER=mock`을 쓴다.** 실 코레일 API에 30초 틱을 붙이면 호출 예절 한도를 순식간에 넘긴다. 프론트만 만질 때는 스케줄러도 꺼둔다:

```bash
ADAPTER=mock SCHEDULER_ENABLED=false uv run uvicorn app.main:app --workers 1
```

`ADAPTER=korail2`로 실연동하려면 앱 설정 화면에서 코레일 계정을 연결하고(`.env`가 아니라 DB에 사용자별로 암호화 저장된다), 정차역·역 마스터를 미리 적재해야 한다:

```bash
# 역 마스터 — 공공데이터포털 CSV를 data/reference/ 에 두고 (--dry-run 으로 먼저 확인)
uv run python scripts/load_stations.py

# 정차역 캐시 — .env 의 DATA_GO_KR_SERVICE_KEY 가 필요하다
uv run python scripts/load_train_stops.py
```

정차역 캐시는 정적 참조가 아니라 **최근 운행일 실적**이다. 열차번호는 개정으로 바뀔 수 있으므로 주기적으로 다시 적재해야 신선도가 유지된다.

### 배포

컨테이너 1개(`Dockerfile` + `docker-compose.yml`)를 EC2 t4g.nano(**Ubuntu 24.04 LTS arm64**,
D-42)에서 돌리고 Tailscale로 접근한다. **절차는 [DEPLOY.md](./DEPLOY.md)를 따른다** —
조용히 틀리는 지점(arm64 / 스왑 / `--workers 1` / `SECRET_KEY`·VAPID 이관 / WAL DB 이관 /
`docker save`의 중첩 index)이 거기 정리돼 있다.

```bash
docker compose up -d --no-build     # 이미지는 Apple Silicon 맥에서 빌드해 올린다 (D-40)
./scripts/deploy_check.sh           # 배포 상태를 한 번에 점검
```

새 클론에서는 시크릿 유출 방지 훅을 한 번 켠다:

```bash
git config core.hooksPath scripts/hooks
```

## CI

`dev`·`main` 푸시와 PR에서 GitHub Actions가 돈다 (`.github/workflows/ci.yml`, → D-44).
**배포는 하지 않는다.**

| 잡 | 내용 |
|---|---|
| `test` | `uv sync --locked` + `pytest` |
| `build` | `ubuntu-24.04-arm`에서 **네이티브 arm64** 이미지 빌드 + 스모크 (arm64 / KST / uid 1000 / `/healthz` / 스케줄러 기동 로그). 프론트 `vite build`도 이 안에서 검증된다 |
| `secrets` | pre-commit 훅과 **같은 규칙**을 추적 파일 전체에 적용 (`scripts/secret_scan.py`) |

`secrets` 잡은 훅을 대체하지 못한다 — `.env`의 실제 값 대조는 러너에 `.env`가 없어
불가능하다. 훅을 켜는 일은 여전히 필요하다.

## 주의

- 코레일 **비공식 API**(korail2 역공학 결과물)를 사용한다. 언제든 깨질 수 있고, 자동화 조회는 약관 회색지대이므로 **정차역당 1~2회로 조회를 최소화**하도록 설계돼 있다. 공격적 폴링 금지.
- 코레일이 도입한 안티봇(`x-dynapath-m-token`)을 우회하는 코드에 의존한다. 앱 업데이트로 토큰 스킴이 바뀌면 깨진다 — 개인용·저빈도·조회 전용이라는 전제 위에서만 성립하는 선택이며, 그 판단 근거는 PLAN.md D-22에 남겨두었다.
- 개인용 도구다. 회원가입은 부트스트랩 1회 후 잠그며, 서버는 Tailscale 내부망에서만 접근 가능하다. **코레일 계정은 사용자마다 각자 필요하다** — 한 계정을 나눠 쓰는 것은 권하지 않는다(동시 세션은 안티봇 관점에서 위험하다).
- 조회 전용이다. 예매/발권 기능은 없고 만들지 않는다.
- 시크릿은 `.env`에만 둔다. `scripts/hooks/pre-commit`이 추적되는 파일로 새어 나가는 것을 기계적으로 막고, CI가 같은 규칙을 다시 돈다 (규칙 본체는 `scripts/secret_scan.py`).
